02 · The big program
The sieve of Eratosthenes, in 250 states.

    
The largest program the network runs, and the one the numbers later on refer to. A 2,000-year-old way to find prime numbers, written as a Turing machine of 250 states and 680 rules, then run by TLF to find every prime up to 1,680.

  

  

    
1 · The idea
Cross out the multiples
Write out the numbers. Take the first one not crossed out, 2: it is prime, so cross out every second number after it. The next one left, 3, is prime: cross out every third. Then 5, then 7. Whatever is never crossed out is prime.

    

  

  

    

      2 · Written as a Turing machine
      
The tape is the numbers

      
Cell n of the tape stands for the number n: it holds 1 while n may be prime, and 0 once it is crossed out. For each k in turn, the machine looks at cell k. If it is still 1, k is prime: the machine walks right to the end of the tape, crossing out every k-th cell, then walks back and moves on to k + 1.

      
A Turing machine has no counter to say “every k-th”, so it counts with states: a chain of k states for each prime k, one state per step of the count. To sieve up to 1,680 it needs strides up to 40, and that is what makes it big.

      

    

    

      
The whole of stride 3

03 · How it differs from your mom's Transformers
These are not hand-coded weights, they are learned by gradient descent

    
Papers on Turing-complete transformers mostly do one of two things: set the weights by hand, or coax a giant pretrained model into following rules. This one trains a small network on steps of a universal machine, then checks every step it takes.

  

  

    
A · Built by hand
Weights written as a proof
Each weight is chosen so the layers carry out a construction: a Turing machine, or a one-instruction computer whose program sits in the input. Nothing is learned. The classic proof assumes numbers of unbounded precision, which no real machine has.

      
Pérez, Barceló, Marinković · Attention is Turing-Complete · JMLR 2021Giannou et al. · Looped Transformers as Programmable Computers · ICML 2023, arXiv 2301.13196Bates · A PyTorch Library of Turing-Complete Neural Networks · arXiv 2605.08150

    
B · Found in a giant model
Rules carried in the prompt
A pretrained language model, weights untouched, is given a system prompt that makes it apply the 2,027 rules of a universal Lag system, one generated token at a time, as its context window slides along. Universality is shown to be there even before training; training makes it easier to program.

      
Schuurmans, Dai, Zanini · Autoregressive LLMs are Computationally Universal · arXiv 2410.03170Lewandowski, Machado, Schuurmans · Universal computation is intrinsic to language model decoding · arXiv 2601.08061

    
C · Learned from steps · this work
Rules learned into the weights
The same Lag-system decoding, with a window of three tokens. The universal machine's step table is not in a prompt: gradient descent put it in 23,844 weights, from steps of random machines only. It runs programs it never saw, and every step of every run we report is checked against the exact rule.

04 · Tiny Lil Fella (TLF)
The tape is the transcript, not the context.

    
A Turing machine needs memory without bound. The usual picture puts it in the context window, so the window has to grow. TLF keeps its context at three tokens and writes its memory out: the transcript it leaves behind is the tape.

  

  

    
The usual picture
Memory is the context window
A large model attends to every cell it holds. Whatever slides out of the window is gone, so a bigger computation needs a longer window, and in the classic proofs, more precision too. (Lag-system constructions also write their memory out, but read it through a long window.)

      
Memorythe context window
Read per stepall of it
More tape meansa longer window

    
Tiny Lil Fella
Memory is the transcript
Each row is one ring of the transcript: the universal machine's whole tape at one moment, its head in orange. The network reads three tokens of the newest ring and writes one into the next. Rings pile up behind it; the memory grows on paper, not in the network.

      
Memorythe transcript, without bound
Read per stepthree tokens
More tape meanslonger rings; the network does not change

  

  
One ring, one step.
A ring is a whole configuration of the universal machine. The window crosses it once, writing the next ring as it goes; when it is through, the machine has taken one step.

  

    
1 · ReadThree neighbouring tokens of the newest ring.

    
2 · WriteThe token for the middle one's place in the next ring, appended to the transcript.

    
3 · SlideOne token to the right. Nothing else is remembered between passes.

    
4 · StepAcross a whole ring, the next one is complete: one step of the universal machine.

05 · Constraints
Every limit of a Turing machine has a counterpart in TLF.

    
A Turing machine is defined by what it may not do: see more than one cell, move more than one cell, hold more than finitely many states. Those limits are exactly what let a window of three tokens run one.

  

  

    
A Turing machine
One cell, one move, one state
A finite control, in one of finitely many states, over a head on one cell. Each step it reads that cell, writes it, moves one cell left or right, and changes state. The tape never runs out. Here it runs the two-state busy beaver.

    
Tiny Lil Fella
Three cells make the next one
The same machine through time: each row is a ring, the next ring below it, the head in orange. A step only touches the head's cell and moves the head one place, so each cell of the next ring depends on three cells of this one. Those cones are why a window of three is enough.

  

  

    
ConstraintThe Turing machineTLF

    
StatesFinitely many. The universal machine has 82↔Finitely many tokens: the head is a token, state:symbol, 1,313 of them

    
AlphabetFinite: 37 symbols on the universal machine's tape↔A vocabulary fixed at training: 1,351 tokens in, 1,356 outputs

TimeOne step↔One ring: as many passes as the ring is long

  

  

    
Where TLF is stricter
A Turing machine's table is given. TLF's is learned, so it carries three limits a Turing machine never has.

    

      
0.004%of all the inputs it could ever be shown were in its training data. An input is three tokens; its 1,351 tokens make 2.47 billion of them, and it trained on 100,697. In every run we report, every input it met was right; on a new program, that is shown by checking, not guaranteed in advance.

      
256Its vocabulary is fixed at training: programs over 0, 1 and blank, with at most 256 states, the most the binary addresses can name.

      
247 millionforward passes for one step of the 250-state sieve. Memory is free; time is not. A delta decoder reads only the windows that changed: for the sieve, 1 in 1,859.

    

    
How it can err
The network is a learned function. Shown an input unlike anything it trained on, it can choose the wrong token, and an earlier version did: running a program with 256 states, it met an input that random machines almost never produce, and wrote a token that sent the universal machine to the wrong state. One wrong token is enough. Nothing corrects the transcript, so everything after it is wrong. We closed that gap by adding training machines that produce such inputs, and we check every run against the universal machine's exact rule.

      The busy beaver
6 steps, 4 ones

      
A _ -> B 1 R
A 1 -> B 1 L
B _ -> A 1 L
B 1 -> halt 1 R

      
The longest any two-state machine runs before stopping. Four machines tie: two mirror-image pairs, each pair differing only in the last move.

    

    

      Why 7 steps is enough
      
No two-state machine that halts takes more than 6 steps: that is a known result. So any machine still running at step 7 never halts, and a 7-step limit sorts all 20,736 exactly.
